## 배경과 제약

후속 보조 옵션·숫자취소·저장 복원 계약을 추가하기 전타입 검사로상태/Action경계를명확히한다.
Native ESM·DOM 독립엔진·게임런타임외부 의존성없음과기존 게임동작을 보존한다. 이번명세는코드전환/설치승인이아니다.

## 검토한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| JS+JSDoc유지 | 빌드추가 없음 | 사용자가 정한TS원본 전환목표미충족 |
| Vanilla TS+tsc | 기존모듈재사용·타입 검사·런타임패키지불필요 | 컴파일/정적 준비/배포 경로정비필요 |
| React/Next.js·번들러까지도입 | 다른개발 구조사용가능 | 미승인 범위 확대·UI재작성비용 |

## 결정과 이유

Vanilla TS+프로젝트고정TypeScript개발 의존성, strict·noEmitOnError, 최신컴파일 출력대상의Node검사를 선택한다.
src/만 먼저 TS로전환하고서버/테스트JS는유지한다. TypeScript추가를런타임라이브러리전면허용으로해석하지 않는다.
.build/는개발검증출력, dist/는게임공개자산만으로구성한다. 생성 출력을커밋하거나직접편집하지 않는다.
GitHub Actions에서설치·타입 검사·회귀·정적 빌드를통과한dist를Pages에배포한다.
원본/생성물 동일 경로 혼용·기존 캐시 출력 검사·브라우저에 .ts 직접 제공을금지한다.

## 영향·전환

개발 설치·lockfile·tsconfig·검증/서버명령·정적 자산준비·Pages설정·문서갱신이 007에 필요하다.
현재D-001의판단이잘못됐다는뜻이아니며당시이유는보존한다.
007에서실제 언어/도구/배포전환과검증을마친시점에D-001의상태를대체됨으로바꾸고양방향링크·목록·architecture를 갱신한다.
기존단계별 완료와이번계획채택은 007구현완료가아니다.

## 재검토 조건

게임런타임의존성·번들러·Node테스트TS 전환·모바일패키징·SSR이필요하면 별도판단한다. 임의의TS최신버전을이번문서에서설치하지 않는다.
