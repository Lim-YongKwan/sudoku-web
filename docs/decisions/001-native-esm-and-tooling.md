## 배경과 제약

순수 웹 기술과 모듈 경계를 학습하고 여러 개발자·AI가 같은 실행·검증 방식으로 협업해야 한다.
사용자는 번들러·외부 라이브러리 없는 Native ESM과 HTTP 실행, Node 내장 개발 도구를 명시했다.

## 검토한 대안

| 대안 | 장점 | 제약 |
|---|---|---|
| Native ESM + 로컬 HTTP + Node 내장 테스트 | 직접적인 모듈 구조, 외부 패키지 설치 없음 | 개발용 Node·서버 준비 필요, DOM은 실제 브라우저 확인 |
| 단일 classic script와 file:// | 단순한 파일 열기 | 모듈 계약 학습과 분리 요구에 맞지 않음 |
| 번들러·외부 테스트 프레임워크 | 풍부한 개발 도구 | 사용자 지정 범위와 외부 의존성 없음 원칙에 맞지 않음 |

## 결정과 이유

브라우저 Native ESM, 시맨틱 HTML, CSS Grid/Flexbox를 사용한다.
Node.js 22 이상은 내장 HTTP 서버와 node:test·node:assert/strict에만 사용한다.
package.json은 type: module과 start·test 명령을 제공하며 외부 의존성을 추가하지 않는다.
게임 백엔드·빌드 번들은 없다. HTTP 서버와 테스트 API가 브라우저 게임 로직에 섞이지 않게 한다.

## 영향과 후속 조치

기본 Node 16.20.2 외에 기존 Node 24.22.1을 확인해 세션 내 선택으로 검증했다. 시스템 설치·전역 PATH는 바꾸지 않았다.
DOM·키보드·반응형 확인은 실제 브라우저 증거가 필요하다. 문서의 예정 명령을 실행 성공으로 기록하지 않는다.
정적 HTTP 자동 검사·npm 실행은 수행했다. 실제 브라우저·추가 junction 검사·서버 종료의 잔여 조건은 사용자 전체 테스트 통과와 확인 보고로 해제했다. 상세 근거는 001과 04 리뷰 기록을 따른다.

## 재검토 조건

외부 의존성 도입, 배포용 번들, 서버 저장·동기화 요구가 생기면 새 결정으로 검토한다.
