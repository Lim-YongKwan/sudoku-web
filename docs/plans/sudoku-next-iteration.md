## 007 — TypeScript 경계

- Vanilla TypeScript다. React·Next.js·Ionic·Capacitor·번들러를 도입하지 않는다.
- 게임 원본 src/를 .ts로 전환한다. scripts/*.mjs·Node 단위 테스트·브라우저 fixture JS는 이 작업에서 JS를 유지한다.
- 개발 의존성은 TypeScript 컴파일러만 허용한다. 런타임 dependencies는 비워두고 외부CDN을 사용하지 않는다. 추가 개발 패키지는 이유·영향을 별도 검토한다.
- 엄격한 타입 검사, 컴파일 오류 시 출력 금지, 기존 런타임 입력 검증을 병행한다. any/단언/검사 무시로 계약을 우회하지 않는다.
- 원본의 상대 import는 출력될 .js 경로를 기준으로 정하고 TypeScript와 Node ESM·브라우저 모두에서 해석되는 설정을 검증한다.
- .build/는 컴파일된 src와 개발용 HTML/CSS·browser fixture를 모은 로컬 검증 출력이다. dist/는 배포용 index.html·styles/·컴파일된 src/만 담는다.
- 원본 JS/TS를 같은 위치에 수동 이중 관리하지 않는다. 출력은 매번 깨끗이 재생성하고 Git에서 제외한다. tests/docs/scripts/package/config가 배포 dist에 섞이면 안 된다.
- 새 npm 명령은 구현 후 활성화한다. 예정 명령: npm ci, npm run typecheck, npm run build:dev, npm test, npm run build, npm start.
- build:dev는 .build 재생성, test는 최신 build:dev 후 Node 검사, start는 최신 build:dev 후 해당 출력의 HTTP 제공, build는 타입 검사·컴파일과 dist 구성이다. 서로 순환 호출하지 않는다.
- 기존 tests의 게임 import·실제 HTTP 대상은 최신 .build 산출물을 보게 수정한다. 원본에 남은 옛 .js나 이전 출력으로 성공하는 검사는 허용하지 않는다.
- GitHub Pages는 GitHub Actions에서 npm ci→타입/테스트/빌드→dist artifact 배포로 전환한다. 실패한 빌드는 배포하지 않는다. 실제 설정 전환은 007 구현 범위이며 이번에 실행하지 않는다.
- [AGENTS 수정안](agents-typescript-proposal.md)을 007 시작 때 적용하고 실제 성공한 명령/경로로 갱신한다. 그 전에는 루트 AGENTS와 D-001 현재 지침을 유지한다.

### 스톡

스톡 표시는 정답/유효 배치 판정이 아니다. 10개 이상도0스톡으로 표시하며 추가 오류·입력 제한을 만들지 않는다.
9개 미만으로 줄면 회색을 해제한다. 회색만으로 disabled를 설정하지 않는다. 생성/완료 중 기존 입력 잠금은 그대로다.

CLEAR_CELL로 최근 입력 칸의 실제 숫자를 지우면 null, 다른 칸을 지우면 기존 최근 입력을 유지한다.

## 012 — 숫자만 실행 취소

- 숫자 입력·삭제·덮어쓰기로 values[index]가 실제로 달라진 경우만 한 단계 기록한다. 메모 모드·메모 삭제만 한 CLEAR_CELL·단서/no-op는 제외한다.
- 기록은 대상index·beforeValue·afterValue·변경 전후 lastInputIndex의 작은 역변경 자료다. 전체 GameState·notes 스냅샷을 되돌리지 않는다.
- UNDO_NUMERIC_EDIT 한 번에 최신 숫자 변경 하나를 제거·취소한다. 여러 번 누르면 이전 숫자 변경을 차례대로 되돌린다. Redo·키보드 단축키는 이번 범위 밖이다.
- 메모를 여러 번 바꾼 뒤 취소해도 가장 최근 숫자 변경을 되돌린다. 다른 셀의 메모는 유지한다.
- 예: 6삭제→그 빈칸에 메모1/3추가→취소는6복원·그 칸 메모 비움이다. 숫자가 있는 칸에 메모를 두지 않는 기존 규칙 때문이다.
- 0을 복원할 때 과거 메모를 재생성하지 않는다. 현재 남은 유효 메모는 유지한다. 대상 외의 메모·값은 변경하지 않는다.
- lastInputIndex만 기록 기준으로 복원한다. 현재 선택/포커스·옵션·난이도·requestId·시작 시각은 과거로 덮어쓰지 않는다. 타이머는 계속 진행한다.
- 새 게임 요청·013 불러오기 성공 시 history를 비운다. 완료/생성/실패/idle에서는 취소 불가다. 비어 있으면 버튼disabled.
- 메모를 건너뛰는 숫자 취소라는 점을 버튼 설명/도움말로 전달한다. 실행 취소용 토글은 만들지 않는다.
- 내부 기록 상한은 구현 시 명시·검증한다. 메모 변경이 숫자 취소 한 단계를 소비해서는 안 된다.

## 013 — 수동 저장·이어하기

### 사용자 흐름

- 같은 브라우저·origin의 localStorage에 한 슬롯만 수동 저장한다. 자동 저장·클라우드·계정·기기/도메인/iOS 앱 간 자동 동기화는 제외한다.
- playing에서만 저장한다. 기존 슬롯이 있으면 덮어쓰기 확인, 취소하면 기존 저장본/현재 게임 모두 유지한다.
- 저장 이후 변경은 자동 반영하지 않는다. 저장은 읽기 전용 스냅샷 생성이며 현재 게임·타이머·history를 변경하지 않는다.
- 시작/새로고침에 유효 저장본이 있으면 이어하기/새 게임 선택을 보여준다. 선택 전 새 퍼즐을 미리 생성하지 않는다. 생성기가 없는것처럼 가정하지 말고 초기 start 흐름을 조정한다.
- 플레이 중 불러오기는 현재 게임 교체 확인 후 수행한다. 취소/복원 실패 시 현재 게임을 보존한다.
- 새 게임을 선택해도 기존 저장본은 유지한다. 다음 수동 저장의 확인 후에만 교체한다.
- 로딩 성공 후 선택한 칸·최근 입력·퍼즐/입력/메모/난이도·경과 시간을 복원한다. 보조 옵션 둘은false, history=[], noteMode=false, error=null, completionDialogOpen=false로 초기화한다.
- 완료된 게임 저장·점수/완료 이력 보관은 제외한다.
- 완료 시 슬롯이 현재 gameId와 같으면 그 슬롯만 삭제하는 것을 명세 기본 정책으로 둔다. 다른 게임의 저장본은 보존한다. 삭제 실패는 완료/잠금을 되돌리지 않고 안내한다.

### 저장 형식·복원 경계

- 버전1 JSON. gameId·schemaVersion·savedAtEpochMs·puzzle·values·notes(number[][])·selectedDifficulty·activeDifficulty·selectedIndex·lastInputIndex·elapsedMs를 기록한다.
- gameId는 새 게임 성공 때 부여하고 저장/복원에서 유지한다. 같은 퍼즐 배열만으로 게임 식별을 대신하지 않는다.
- Set·단조 시계의 startedAtMs/stoppedAtMs·requestId·AbortController·구독·UI DOM·옵션·취소 history는 저장하지 않는다.
- JSON.parse 결과는unknown으로 취급한다. schemaVersion·필드 타입·81셀/81메모·숫자 범위·퍼즐 유효성·단서 일치·난이도/목표 빈칸·선택/최근 입력의 유효성을 런타임 검증한다.
- 현재 입력 values의 충돌·잘못된 풀이를 저장/복원할 수 있어야 한다. 정답 비교·자동 수정·빈칸 채우기를 하지 않는다. 이미 유효 완성된 payload는 진행 중 저장 계약 위반으로 분류한다.
- 각 notes는 독립 Set으로 복원하고 실제 값이 있는 셀의 메모·범위 밖 값 등 형식 위반은 명시한 오류 정책으로 처리한다. 검증 실패로 기존 현재 게임/저장본을 임의 삭제하지 않는다.
- 복원 성공 때 진행 생성 취소·tick/구독 누적 방지·새 requestId로 과거 응답 차단을 기존 효과 흐름에 통합한다. 실패/취소가 먼저 현재 상태를 비우지 않게 한다.
- 저장 접근 차단·용량 초과·JSON 손상·미지원 버전에서 일반 안내와 새 게임/현재 게임 사용을 제공한다. setItem 성공 전에 저장 완료를 알리지 않는다.

### 시간

예정 timer 확장: baseElapsedMs(새 게임0) + startedAtMs/stoppedAtMs.
누적 경과=baseElapsedMs + max(0,(종료 또는now)-startedAtMs), 표시 시 초 내림.
복원은 baseElapsedMs=저장elapsedMs, startedAtMs=현재 단조 시각, stoppedAtMs=null이다.
05:30에 저장해 다음 날 불러오면05:30부터 시작한다. 저장/앱 종료 이후 복원까지의 벽시계 시간은 더하지 않는다.
열린 플레이 세션의 숨김 탭 시간 포함 규칙은 유지한다. savedAtEpochMs는 표시/진단용이며 게임 시간 계산 기준이 아니다.
