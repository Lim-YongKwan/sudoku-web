## 사용자에게 안내한 잔여 확인 절차 — 최종 확인 전 이력

[03 구현 기록의 실행 절차](typography-008.md)를 따른다. npm start가 출력한 주소의 실제 게임과 /tests/browser/typography.html을 사용한다.

1. playing·conflict·generating·completed 네 상태 각각에서 “실측 검사”를 누른다. checks가 모두true인지 기록한다. generating은 숫자/메모0, playing/conflict는18개 숫자·9개 메모, completed는81개 숫자·메모0을 기대한다.
2. 완료 상태에서 고정 셀 배경과 입력 셀 배경이 다른지 확인한다. 1~9의 같은 숫자, 특히3·6·8의 굵기·크기·정렬을 비교한다. Trebuchet MS가600/700을 같은 실제 굵기로 표시해도 배경·색상 구분과 실제 가독성을 따로 판단한다.
3. 320px·1280px 및 iPhone/Safari 또는 대체 터치 환경에서 메모·오류 !·충돌 테두리·Tab 포커스·잘림·가로 넘침을 확인한다. 실제 게임의 입력/메모/완료 dialog·포커스·잠금도 확인한다.
4. 실제 렌더링 서체를 개발 도구 Rendered Fonts/Fonts로 확인·기록한다. CSS 요청 스택을 실제 선택된 글꼴로 기록하지 않는다. 콘솔 오류도 확인한다.
5. 선택적으로 완료 시연의 첫 단서 배경을 개발 도구에서 입력 배경과 같게 변경한 뒤 실측 검사를 누르면 clueBackgroundDistinct가false여야 한다. 새로고침해 인라인 변경을 제거한 뒤 정상 결과를 재확인한다. 실제 게임 데이터는 변경하지 않는다.
6. 전체 테스트의 권한 skip을 사용자 환경에서 확인하고, Ctrl+C로 서버를 종료한다. 실제 결과를 보고한 뒤008 완료 여부를 판단한다.

커밋·push·PR·Pages 변경과 후속 태스크 구현은 수행하지 않았다.
