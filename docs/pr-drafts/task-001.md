## PR 본문 초안

### 해결하는 문제와 변경 후 동작

순수 JavaScript 스도쿠 개발을 시작할 때 공통 HTTP 실행·검증 환경이 없었다. 이제 Node.js 22 이상에서 외부 패키지 설치 없이 npm start로 준비 페이지를 제공하고, 브라우저에서 Native ESM 초기화 표시를 확인할 수 있다. npm test는 Node 내장 runner로 18개 환경 검사를 실행한다.

### 포함·제외 범위

- 포함: package.json의 ESM·Node 기준·실행/검증 명령, 루프백 정적 서버, 최소 HTML/CSS/ESM 준비 화면, 실제 HTTP·CLI 회귀 검사, 실행 안내와 작업·아키텍처·결정 반영 기록.
- 제외: 스도쿠 엔진·보드·입력·메모·난이도·타이머·게임 완료 UI. 외부 의존성·번들러·게임 백엔드도 없다.

### 주요 변경과 리뷰 수정

- 서버는 127.0.0.1에 바인딩하며 기본 포트는 8080이다. PORT로 변경하고 테스트에서는 임시 포트를 사용한다.
- 공개 경로와 MIME을 제한하고 원시·인코딩 경로, 숨김 경로, 루트 경계, 링크의 실경로에 공개 정책을 적용한다. GET/HEAD를 지원하고 없는 파일·허용되지 않은 요청·포트 충돌을 처리한다.
- CLI 시작 안내의 미정의 HOST 참조를 실제 바인딩 주소로 수정했다.
- 시작 후 오류에 열린 서버를 정리하고 중복 종료 요청을 한 번의 정리로 합쳤다.
- 실제 CLI 자식의 시작 → HTTP 응답 → 소유 부모 IPC 종료 → exit 0 → 포트 닫힘 회귀를 추가했다. HTTP 종료 엔드포인트는 없다.
- 문자열 포트를 숫자로 정규화하고 잘못된 타입을 거부한다.
- UI는 환경 준비 표시만 제공하며 후속 게임 기능이 구현된 것처럼 표시하지 않는다.

### 검증

| 수행 주체 | 환경·명령 또는 절차 | 결과 |
|---|---|---|
| Codex 도구 | Node 24.22.1·npm CLI 8.19.4, npm test | 당시 17 통과·0 실패·1 skip. Windows junction 생성 EPERM |
| 사용자 후속 검증 | 안내한 Node 22 이상 실행·테스트 절차 | 18 통과·0 실패·0 skip 보고. 당시 미검증 링크 검사 포함 |
| 사용자 실제 브라우저 | 로컬 HTTP 페이지의 ESM 초기화·Console 확인 | 초기화 확인·콘솔 오류 없음 |
| 사용자 서버 정리 | 안내한 이전 서버 및 새 실행 서버 종료 확인 절차 | 서버 종료 확인 보고 |
| 문서 정합성 | 작업·목록·현재 구조·결정 반영 범위·상대 파일 링크 대조 | 완료 상태·문서 연결 동기화 |

도구 자동 검사는 HTTP·HTML/JS/CSS MIME·HEAD·404/405·경로 경계·메타데이터·UTF-8·포트 충돌·정상 CLI 수명주기를 포함한다. 수정 전 HOST 오류가 회귀 검사에서 실패했고 수정 후 통과했다.

최종 사용자 확인은 2026-10-23 대화 보고를 근거로 한다. 원시 테스트 출력·사용자 실행 버전 출력·브라우저 이름/버전·PID·스크린샷은 제공되지 않았다. 사용자 확인을 Codex의 직접 브라우저 관찰이나 이전 격리 세션의 직접 종료 로그로 표현하지 않는다.

### 스크린샷

미첨부. 실제 캡처 파일을 전달받지 않아 이미지나 경로를 만들지 않았다.

### 영향·제약과 후속 관계

- 개발용 로컬 정적 서버다. Node 22 이상이 필요하며 기존 시스템 기본 Node 16은 실행 기준을 충족하지 않는다. README의 세션 내 Node 선택 절차를 따른다.
- file:// 더블클릭 실행은 지원하지 않는다. 외부 npm·CDN 의존성과 빌드 단계가 없다.
- 확인된 범위의 중대한 미해결 문제나 필수 검증 잔여 항목은 없다. 도구의 junction·브라우저·종료 입력 제약 이력은 보존한다.
- 시작 이후 예외를 강제로 주입하는 별도 테스트는 미실행이다. 정상 수명주기·포트 충돌은 자동 검증했다.
- 이 초안의 PR 링크·대상 기본 브랜치는 미정이다. 저장소 준비 후 실제 diff·포함 파일과 검증 대상 코드 일치를 확인한다.
- 002 엔진의 선행 작업은 001이다. 팀이 환경 코드·문서를 검토하고 기본 브랜치에 반영한 뒤 002를 시작한다. 002~005는 아직 예정이다.
