## PR 본문 초안

### 해결하는 문제와 변경 후 동작

스도쿠 보드를 검증·풀이하고 유일한 해답을 갖는 퍼즐을 생성할 엔진이 필요했다. 이제 DOM 없이 같은 Native ESM API를 호출해 보드 충돌·완료 여부, 첫 해답과 최대 2개 해답 수를 확인하고 세 난이도의 퍼즐을 생성할 수 있다.

생성은 정확한 목표 빈칸 수와 유일해를 만족할 때만 성공한다. 탐색·전체 생성에 제한을 두고, 예산 초과·시도 소진·취소를 결과로 구분하므로 후속 UI가 실패·재시도를 처리할 수 있다.

### 포함·제외 범위

- 포함: 보드 API, MRV 백트래킹 풀이·해답 수, 유일해 생성, 난수·시계·task 양보 주입, 전체/개별 예산·취소, fixture와 테스트, 아키텍처·D-002 반영 범위·작업 기록.
- 제외: 보드 렌더링·게임 store·입력·메모·로딩/실패 UI·타이머·완료 dialog. 이번 단계의 기본 화면은 기존 환경 준비 화면이다.
- 외부 npm·CDN 패키지와 번들러는 추가하지 않았다. 001 서버·package.json·환경 테스트는 변경하지 않았다.

### 주요 구현

| 파일 | 책임 |
|---|---|
| [board.js](../../src/core/board.ts) | dense 81셀·정수 0~9 검사, 행/열/박스의 모든 충돌, 빈칸·유효성·원본 단서 완료 판정 |
| [solver.js](../../src/core/solver.ts) | 입력 복사·MRV·비트 마스크 탐색, Promise 풀이·해답 수, 실패·불완전 탐색 구분 |
| [generator.js](../../src/core/generator.ts) | 난수 완성 보드·Fisher–Yates 셀 제거·제거별 유일해 검사·난이도 목표 |
| [search-runtime.js](../../src/utils/search-runtime.ts) | 옵션·난수·단조 시계 검증, 노드 누계·공유 예산·task 양보 |
| [boards.js](../../tests/fixtures/boards.js) | 유일해·충돌·복수해·무해답·단서 변경 fixture와 재현 가능한 난수 |
| [board 검사](../../tests/board.test.js)·[solver 검사](../../tests/solver.test.js)·[generator 검사](../../tests/generator.test.js) | 결과·불변성·제한·취소·seed·독립 기준 풀이 검증 |

- 유일해의 증거는 countSolutions의 complete/count=1이다. limit-reached/count=2는 복수 해답이며 budget-exceeded/count=1을 유일해로 취급하지 않는다.
- easy/normal/hard 목표 빈칸은 35/45/50이다. 빈칸 기반 간이 난이도이며 논리 풀이 난이도를 보장하지 않는다.
- 기본 생성 제한은 시도 8회·전체 1,000,000노드·5초, 개별 탐색 100,000노드·최대 2초다. 기본 128노드와 제거 사이에 다음 task로 양보한다.
- 개별 탐색 제한은 제거 복구·다음 시도, 전체 제한은 전체 실패다. 동시 관찰 시 취소 → 전체 시간 → 전체 노드 → 시도 제한 순으로 판단한다.
- 생성 성공에 해답을 반환하지 않고 실패에 부분 puzzle을 포함하지 않는다. core에 DOM·Node 전용 import가 없다.

### 리뷰에서 해결한 사항

- 옵션을 spread하는 과정에서 상속된 signal·now·yieldControl이 누락돼 이미 취소된 생성도 성공할 수 있었다. 원본 options에서 hooks를 직접 읽도록 수정했다. 회귀 검사가 수정 전 success/aborted 불일치로 실패했고 수정 후 통과했다.
- 개별 2초 탐색 제한이 전체 시간 제한과 구분되어 재시도되는 검사를 추가했다.
- 동일 solver를 이용한 생성 재검증에 더해, 별도 직접 행/열/박스 검사 방식의 기준 풀이와 총 13개 사례를 대조했다. 후자의 두 항목은 검증 보강이며 추가 제품 결함으로 집계하지 않았다.

### 검증 결과

| 독립 기준 풀이 대조 | 복수해 1건·고정 seed로 20셀 제거한 12건, count/status 일치 |

이번 skip은 기존 서버의 Windows junction 생성 EPERM이다. 통과로 표시하지 않았다. 서버 구현·설정·테스트는 바뀌지 않아 현재 서버 17개 통과와 [001에서 사용자가 확인한 전체 18개 통과](../review-001.md)를 함께 적용해 완료 판단했다. 이전 사용자 확인의 원시 로그는 미제공이며 이번 실행 결과로 표현하지 않는다.

이번 05 작업은 문서 작성이며 테스트를 재실행하지 않았다. 위 수치는 [04 리뷰의 실제 실행 결과](../review-002.md)다.
