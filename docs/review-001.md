R5의 존재 가능성은 코드 흐름으로 판단했으며 이 환경에서 실제 링크 공격을 재현했다고 주장하지 않는다.
새 HTTP 종료 엔드포인트는 추가하지 않았다. IPC 제어는 소유 부모가 생성한 채널에서만 가능하다.
테스트의 실패·timeout 정리는 해당 테스트가 생성한 자식만 대상으로 한다. 다른 Node 프로세스를 종료하지 않는다.

## 자동 검증 — 도구 실행 당시

Node 24.22.1로 기존 npm CLI 8.19.4의 test를 실행했다. 세션 PATH에서 lifecycle의 node도 해당 버전으로 선택했다.

- 전체 18개: **17 통과 / 0 실패 / 1 skip**.
- 추가 성공 CLI 검사: 실제 CLI 실행 → ready host·port 확인 → HTTP 200 → IPC shutdown → 프로세스 exit 0 → 해당 포트 ECONNREFUSED.
- 기존 MIME·HEAD·404·405·원시/인코딩 traversal·Windows 경로·메타데이터·UTF-8·포트·서버 닫힘 검사도 통과.
- skip: Windows 샌드박스가 디렉터리 junction 생성을 EPERM으로 거부. 링크 경계 검사는 통과로 표시하지 않는다.
- 최종 실행은 force-exit 없이 종료했다. 외부 패키지 설치나 시스템 Node·전역 PATH 변경은 없다.
