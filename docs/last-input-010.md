## 구현

- GameState에 readonly lastInputIndex: number | null을 추가했다. 초기 상태와 표시용 상태는 null이다.
- 실제 값이 달라진 숫자 입력·덮어쓰기만 해당 index로 갱신한다. 동일값 재입력, 단서 입력, 메모 추가/제거, 선택/이동, 옵션/난이도 변경은 최근 입력을 갱신하지 않는다.
- 최근 숫자를 지우면 null, 다른 숫자나 메모를 지우면 기존 index를 유지한다. 초기화·새 요청·생성 성공/실패·완료에는 null이다. 완료 후 기존 입력 잠금을 유지한다.
- src/core/last-input.ts의 런타임 검증을 store 진입과 셀 모델 투영에서 공유한다. null 외에는 playing 상태의 값이 있는 편집 가능한 0~80 정수 index만 허용한다. 원본 보드 형식은 호출자가 먼저 검사한다.
- 보드 모델 recent → .is-last-input → 숫자 갈색(#985619)과 밑줄로 표시한다. aria-label에 최근 입력을 추가하고 메인 화면 범례에 밑줄 의미를 안내한다.
- 기존 셀 DOM을 재사용한다. 선택/단서 배경, 충돌 테두리·느낌표, 포커스 outline은 기존 규칙을 유지한다. 새 타이머/이벤트/보조 옵션을 추가하지 않았다.
- 012 실행 취소·013 저장 복원을 위한 필드와 검증 계약만 마련했다. 해당 기능과 011 같은 숫자 강조는 구현하지 않았다.
- AGENTS.md의 기술/협업 규칙은 바뀌지 않아 수정하지 않았다.

## 브라우저 시도와 남은 필수 확인

computer-use로 실행 중인 Chrome 새 탭 창을 선택했으나, 도구가 현재 URL을 충분히 확신하지 못해 이번 턴의 조작을 중단했다. 페이지 접속·화면 입력·콘솔 확인은 수행하지 못했다. HTTP 응답 성공은 브라우저 ESM 실행 성공으로 간주하지 않는다. 도구 중단 후 추가 UI 조작은 하지 않았고 검증 서버는 종료했다.

다음 04에서 코드 리뷰와 아래 실제 검증을 수행한다. 아직 사용자 확인 보고도 없으며 완료로 처리하지 않는다.

1. Node 22+ 환경에서 npm test, npm start를 실행하고 서버가 출력한 HTTP 주소를 사용한다.
2. /tests/browser/interaction.html의 일반 fixture에서 1행3열(index2)에 4 입력: 갈색 밑줄 1개, 보고서 lastInputIndex=2, recentCells 한 개와 접근성 이름 최근 입력을 확인한다.
3. 1행4열에6 입력 후 1행3열을 선택하여4를 다시 입력: 최근 칸은 index3을 유지한다. 8로 덮어쓰면 index2로 옮겨진다.
4. 다른 칸 선택/방향키·외부 폼·메모 추가/제거·스톡 ON/OFF 후에도 최근 입력이 유지되는지 확인한다. 30초 이상 대기해 사라지지 않는지 확인한다.
5. 최근 칸에5를 입력하여 충돌을 만든 뒤 다른 칸 선택: 갈색 밑줄과 중복 느낌표/테두리·단서 배경·포커스 링이 구분되는지 확인한다.
6. 다른 숫자/메모를 삭제하면 유지, 최근 숫자를 삭제하면 null/밑줄0개인지 확인한다.
7. 완료 직전 fixture의 1행3열에4 입력 후 완료 잠금과 최근 표시 해제를 확인한다. /tests/browser/controls.html에서는 완료 대화상자·닫기·포커스도 확인한다.
8. 메인 게임의 새 게임/난이도·새로고침, 실패 fixture/재시도 후 이전 표시가 없는지 확인한다.
