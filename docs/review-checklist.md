# 스도쿠 코드 리뷰 체크리스트

이 문서는 향후 코드 작업의 공통 기준이다. 이 원본의 체크 표시는 개별 작업의 실행 결과가 아니다. 각 작업에서 적용한 항목·실제 결과·미실행을 별도로 기록한다.
각 태스크의 관련 항목만 적용하고 실제 결과는 해당 작업 문서에 기록한다. 미구현 후속 기능을 현재 작업의 결함으로 취급하지 않는다.

## 범위와 구조

- [ ] 지정한 작업의 목표·범위·계약·선행 코드가 현재 체크아웃과 일치한다.
- [ ] core에 DOM 의존성이 없고 UI 이벤트 → Action → 상태 → Render 흐름을 지킨다.
- [ ] 렌더러가 상태를 직접 변경하지 않는다. 중복 이벤트 등록과 불필요한 상태 중복을 피한다.
- [ ] 외부 npm·CDN 라이브러리와 번들러를 사용하지 않는다.
- [ ] 이번 작업의 시연 범위와 아직 없는 후속 기능을 구분한다.

## 실행 환경

- [ ] Node 기준과 실제 버전, 실행·테스트 명령을 확인했다.
- [ ] HTTP에서 HTML·JS·CSS가 올바른 MIME으로 제공되고 ESM이 로딩된다.
- [ ] 로컬 서버의 파일 범위, 없는 경로, 포트 오류와 종료 처리가 적절하다.
- [ ] package.json이 실제 설정과 일치하고 설치하지 않은 패키지에 의존하지 않는다.

## 스도쿠 엔진

- [ ] 보드 길이·숫자·빈칸·모순 입력과 반환·실패 계약을 지킨다.
- [ ] 검증·풀이·해답 개수 검사가 입력을 변경하지 않는다.
- [ ] 초기 단서가 유지되고 생성 퍼즐의 해답이 정확히 하나다.
- [ ] 해답 없음·복수 해답·이미 완성된 보드를 재현 가능한 입력으로 확인했다.
- [ ] 생성 시도·탐색 상한, 취소·실패 계약이 있고 장시간 UI를 막지 않는다.
- [ ] 간이 난이도 목표와 실제 논리 난이도를 구분한다.
- [ ] 고정 난수 또는 fixture로 재현 가능한 테스트와 제한 내 실패 경로가 있다.

## 입력·상태·접근성

- [ ] 단서는 수정 불가하며 선택·입력·삭제·메모 전이가 계약에 맞다.
- [ ] 충돌 오류와 숨겨진 정답 비교를 혼동하지 않는다.
- [ ] 클릭·터치·방향키·숫자·Backspace/Delete·화면 컨트롤을 해당 범위에서 확인했다.
- [ ] 보드 밖 입력과 드롭다운 키 입력을 가로채지 않는다.
- [ ] 셀 접근성 이름, 가시적 포커스, 색상 이외의 오류 안내가 있다.
- [ ] 렌더링 뒤 포커스와 선택 상태가 적절하게 유지된다.
- [ ] 320px 폭과 일반 데스크톱에서 보드·컨트롤을 확인했다.

## 게임 제어·시간·완료

- [ ] 새 게임 반복과 생성 중 입력 잠금·실패 안내가 일관된다.
- [ ] 오래된 생성 결과가 최신 게임을 덮어쓰지 않는다.
- [ ] 타이머는 tick 횟수가 아닌 경과 시간을 기준으로 하며 중복 실행되지 않는다.
- [ ] 새 게임 초기화, 숨겨진 탭 시간, 완료 시 정지가 계약과 일치한다.
- [ ] 빈칸·유효성·단서 일치를 모두 확인하고 잘못된 완성은 완료로 처리하지 않는다.
- [ ] 완료 대화상자의 접근성·닫기·포커스 복귀를 확인했다.

## 증거와 문서

- [ ] 관련 자동 검사와 필수 회귀 검증의 실제 명령·결과가 기록됐다.
- [ ] 실제 브라우저 확인과 콘솔 유틸 검증을 구분했다. 미실행·실패를 통과로 표시하지 않았다.
- [ ] 발견 사항과 수정·재검증, 중대한 남은 문제를 작업 문서에 기록했다.
- [ ] architecture.md는 현재 코드와 일치하고 예정 설계는 계획 문서에 있다.
- [ ] 작업·결정 ID·파일명·제목·목록·링크·상태가 일치하고 과거 기록은 보존됐다.
- [ ] 실제 전환 후 기존 결정을 대체됨으로 표시했다. 채택을 구현 완료로 간주하지 않았다.
- [ ] 필수 검증·완료 조건·리뷰가 끝난 경우에만 04에서 완료 처리한다.
- [ ] PR 초안의 스크린샷과 테스트 결과가 실제 근거와 일치한다.
