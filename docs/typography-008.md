## 구현

숫자 전용 글꼴 스택을 "Trebuchet MS", ui-rounded, system-ui, sans-serif로 두고 입력600·단서700을 적용했다. 크기·line-height·Grid 중앙 정렬은 공통이다. 기존 단서 배경과 색상을 유지하며 메모400·오류 ! 800은 분리했다. 숫자 패드도 같은 서체·600을 사용한다.
외부 폰트 다운로드·패키지 설치·src 상태/입력/엔진 변경은 없다. 고정 굵기 폰트는600/700을 같은 굵기로 매핑할 수 있으므로 기기별 실측·육안 판단이 남았다.

## 자동 검증

Node v24.22.1과 기존 고정 TypeScript를 사용했다. npm run typecheck, npm run build:dev, npm run build가 통과했다.
npm test는99개 중98통과·0실패·1skip이다. Windows 디렉터리 링크 권한 제한을 처리하는 서버 검사에 skip 경로가 있으며 전체 통과로 처리하지 않는다. 이전007의 사용자99개 전체 통과와 구분한다. 새 Node 테스트를 CSS 선언 값과 똑같이 작성하지 않고 기존 동작 회귀를 실행했다.
개발 fixture의 node --check도 통과했다. 개발 비교 페이지는 최신 .build에 복사되며 dist에는 포함되지 않는다. 실제 DOM 측정은 아직 실행하지 않았다.

## 브라우저 시도와 서버 종료

computer-use 스킬로 기존 Chrome 창을 선택하고 활성화/화면 확인을 시도했으나 도구가 사용자 physical Escape 중단을 반환했다. 화면 입력을 즉시 중단했고 다른 브라우저/도구로 우회하지 않았다. 브라우저 페이지 열기·스타일 실측·폰트 확인·콘솔 관찰은 미실행이다.
npm start는 PORT=0으로 http://127.0.0.1:50020, PID60908을 출력했다. Ctrl+C 후 “서버를 종료했습니다.”를 확인했고 PTY 종료 코드는 -1073741510이었다. 직접 브라우저 접속 성공을 뜻하지 않는다.

## 04에서 수행할 수동 절차

Node22 이상 환경에서 프로젝트 폴더에서 아래를 순서대로 실행한다. 기본 PATH가 Node16이면 README의 명시적 Node/npm 경로를 사용한다.

~~~powershell
npm run typecheck
npm test
npm run build
npm start
~~~

1. 서버가 출력한 주소에서 게임을 열고 입력·삭제·덮어쓰기·메모, 고정 단서 보호를 확인한다.
2. 같은 주소의 /tests/browser/typography.html을 연다. 첫 행은 고정1~9, 둘째 행은 입력4~9·1~3이다. 같은3·6·8과 나머지 숫자의 굵기·크기·정렬을 비교한다. 셋째 행 첫 셀의 메모1~9도 읽혀야 한다. 이 배열은 게임 가능한 퍼즐이 아닌 렌더러 시연이다.
3. 각 상태 버튼과 “실측 검사”를 누른다. 선택·충돌·! 표시와 생성 중/완료 잠금을 확인한다. checks가 모두true인지 기록하되 육안 확인을 대신하지 않는다. Tab으로 가시적 포커스도 확인한다.
4. viewport320px·1280px에서 가로 넘침·정사각 셀·3x3 경계·글자 잘림·메모 겹침을 확인한다. 실제 앱과 비교 페이지 모두 확인한다.
5. 개발 도구 Rendered Fonts/Fonts에서 실제 렌더링 서체를 기록한다. CSS fontFamily 값은 요청 스택일 뿐 실제 선택된 서체의 증거가 아니다. Trebuchet MS 설치 여부와 iPhone/Safari 또는 대체 모바일 환경의 fallback·굵기 차이를 확인한다.
6. /tests/browser/controls.html에서 실제 완료 dialog·닫기 후 포커스와 입력 잠금을 확인한다. 모바일 터치 또는 터치 에뮬레이션, 콘솔 오류 여부도 확인한다.
7. 터미널에서 Ctrl+C로 종료하고 종료 안내를 확인한다. 실제 수행 결과와 기기·브라우저·서체를008 문서에 기록한다.
