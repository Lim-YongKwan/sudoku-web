## 3. 작업 범위

### 포함

- index.html, styles/main.css, src/ui/board.js를 보드 표시용으로 확장하고 src/main.js에 실제 엔진 초기 생성·렌더 연결을 구현한다.
- tests/browser/board.html에서 고정 fixture를 렌더링한다. 사용자 게임 UI에 테스트·정답 공개 버튼은 넣지 않는다.
- 81셀·3x3 경계·단서/빈칸 구분·접근성 이름·가시적 포커스·320px 반응형을 구현한다.
- 간단한 초기 로딩·실패 안내만 연결한다. 수동 새 게임·타이머·완료 dialog는 후속 작업이다.

### 제외

정식 store·플레이어 숫자 입력·삭제·메모·키보드 이동·화면 숫자 패드·난이도 변경·새 게임·타이머·축하 dialog.

### 유지할 제약

- 외부 의존성과 번들러를 추가하지 않는다. 계획의 계약·단서·유일해·입력 불변·상태 경계를 유지한다.
- 다른 담당자의 변경을 보존하며, 선행 코드가 없는 경우 후속 기능을 임의로 합쳐 구현하지 않는다.

## 기술 계약과 시연 범위

- renderBoard(root, state): void는 계획 7·9절의 상태 필드 중 표시용 값을 읽고 상태·보드·Set을 변경하지 않는다.
- C 단계는 고정 fixture나 main의 읽기 전용 초기 표시 상태를 사용한다. D에서 store로 연결하되 임시 구조로 계약을 바꾸지 않는다.
- main은 generatePuzzle(easy)의 success만 보드에 연결한다. 실패 결과는 오류 안내로 처리하고 가짜 퍼즐로 대체하지 않는다.
- 81개 셀 노드를 유지해 재렌더 때 불필요하게 포커스를 잃지 않는다. 셀은 행·열·값·단서 여부 이름을 가진 button이며 불완전한 ARIA grid를 추가하지 않는다.
- 표시와 포커스 확인만 이번 범위다. roving 방향키 이동·플레이어 이벤트 바인딩은 D에서 연결한다.

시연 범위: HTTP 페이지에 실제 생성 퍼즐이 표시되고, 별도 개발 페이지에서는 고정 보드의 스타일·셀 이름·포커스를 확인한다. 아직 플레이할 수 없다.
