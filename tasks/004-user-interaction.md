## 3. 작업 범위

### 포함

- src/core/game-state.js, src/ui/events.js, tests/game-state.test.js를 만들고 main·board·HTML·CSS를 입력 흐름에 연결한다.
- 클릭·터치·방향키·1~9·Backspace/Delete·화면 숫자 패드·삭제·메모 버튼을 구현한다.
- 선택·메모·충돌 상태 표시와 불변 reducer·store·구독 정리를 구현한다.
- GAME_COMPLETED의 상태·판정 계약은 구현하되 시간 표시와 완료 dialog의 실제 화면 연결은 E에서 수행한다.

### 제외

난이도 변경·수동 새 게임·생성 요청 취소 전체 UI·타이머 표시·완료 dialog. 정답 비교 오류·이웃 메모 자동 삭제·실행 취소·힌트.

### 유지할 제약

- 외부 의존성과 번들러를 추가하지 않는다. 계획의 계약·단서·유일해·입력 불변·상태 경계를 유지한다.
- 다른 담당자의 변경을 보존하며, 선행 코드가 없는 경우 후속 기능을 임의로 합쳐 구현하지 않는다.

## 기술 계약과 시연 범위

- createInitialState·reduceGame·createGameStore와 계획 7~8절 Action을 구현한다. DOM·시계·Promise 효과는 reducer 밖에 둔다.
- Board·Set을 변경 시 복사하고 notes 셀 참조를 공유하지 않는다. getState는 읽기 전용이며 unsubscribe 이후 통지는 없어야 한다.
- 단서 입력·삭제는 no-op, 메모는 빈 편집 셀에만 토글, 실제 값 입력은 해당 메모 삭제, CLEAR_CELL은 값·해당 메모 삭제다.
- 오류는 findConflicts만 사용한다. 완료는 빈칸 없음·규칙 유효·단서 일치를 모두 만족해야 하며 completed에서 플레이 입력은 no-op다.
- roving tabindex로 한 셀만 보드 Tab 진입점이고 방향키는 경계에서 멈춘다. 외부 폼·드롭다운·브라우저 단축키는 가로채지 않는다.
- 초기 실제 퍼즐을 store의 요청·성공 Action으로 연결하고 D 범위에서 입력 후 완료 상태를 전이시킨다. 타이머의 시각 메타데이터는 계약대로 전달하되 interval·완료 dialog는 E로 남긴다.

시연 범위: 표시된 퍼즐을 클릭·터치·키보드·숫자 패드로 편집하고 메모와 충돌 안내를 확인한다. 완료 상태 판정은 되지만 타이머·축하 UI는 아직 없다.
