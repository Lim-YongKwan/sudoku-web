## 기술 계약과 시연 범위

공통 계획 013의사용자흐름·저장 형식·시간 계약을 따른다. 명시적수동 저장만하며저장이후조작을자동 반영하지 않는다.
저장본이 있으면시작 때이어하기/새 게임선택 전새 퍼즐생성을하지 않는다. 새 게임은저장본 유지·옵션OFF·history초기화다.
playing에서저장,덮어쓰기확인취소는변경 없음. 플레이 중불러오기확인취소/검증 실패는현재 게임을 보존한다.
정상복원은퍼즐/값/메모/두 난이도/선택/최근 입력/elapsed를복원하되옵션false·history[]·noteModefalse·dialogfalse로시작한다.
JSON은 unknown으로 검증하고 메모는 81개의 독립 Set으로 복원한다. 타입 선언만으로 저장 값을 신뢰하지 않는다.
형식/단서/퍼즐은검증하지만사용자values의충돌/틀린풀이는허용한다. 정답 비교나자동 수정은하지 않는다.
timer.baseElapsedMs를추가하고저장elapsedMs에서새now기준으로재개한다. 05:30저장→다음 날05:30재개,열린세션숨김 탭시간은포함한다.
성공확정후이전생성취소·requestId증가·tick/구독정리를하므로늦은결과가복원게임을덮어쓰면안된다. 실패/취소는먼저보드를비우지않는다.
새 gameId·저장 gameId를구분해같은 게임완료시만슬롯을정리한다. 다른 게임저장은보존한다. 저장 접근/용량/삭제 오류는게임진행을깨지않게안내한다.

예정 변경 위치: 예정 src/core의저장스키마/복원Action·game-state.ts·utils/time.ts·브라우저 저장adapter·main/controls의시작/확인 UI·검증용fixture·저장/시간/경합검사.
아래 위치·명령은 구현 시 실제 파일/설정에서 확인하며 없는 파일을 이미 존재하는 것으로 보고하지 않는다.
