## 3. 작업 범위

### 포함

- src/core/board.js, solver.js, generator.js와 src/utils/search-runtime.js를 구현한다.
- tests/fixtures/boards.js와 tests/board.test.js·solver.test.js·generator.test.js를 작성한다.
- Board 입력·결과·오류 계약, 입력 불변성, 난수·시계·양보 주입, 전체·개별 예산과 취소를 구현한다.
- 세 간이 난이도의 목표 빈칸·단서·유일해와 제한 내 실패 경로를 검증한다.

### 제외

게임 상태 store·DOM 렌더링·입력·로딩 UI·타이머·완료 dialog. 사용자에게 해답을 노출하는 기능.

### 유지할 제약

- 외부 의존성과 번들러를 추가하지 않는다. 계획의 계약·단서·유일해·입력 불변·상태 경계를 유지한다.
- 다른 담당자의 변경을 보존하며, 선행 코드가 없는 경우 후속 기능을 임의로 합쳐 구현하지 않는다.

## 기술 계약과 시연 범위

- Board는 길이 81 Array, 정수 0~9, 0은 빈칸이다. assertBoard·findConflicts·isValidBoard·isComplete는 계획 3~4절을 따른다.
- solveBoard와 countSolutions는 Promise 결과로 solved·unsolvable·invalid·budget-exceeded·aborted 및 count의 완료 여부를 구분한다. 형식은 TypeError, 옵션 범위는 RangeError다.
- countSolutions는 limit=2만 허용하고 complete/count=1만 유일해 증거다. limit-reached/count=2는 복수 해답이며 불완료 count=1을 성공으로 쓰지 않는다.
- generatePuzzle 성공은 puzzle·difficulty·blankCount·stats이며 해답을 UI로 반환하지 않는다. 실패 이유·통계는 계획 6절 계약을 지킨다.
- 목표 빈칸 easy=35, normal=45, hard=50. 초기 시도 8회, 전체 1,000,000노드·5,000ms, 개별 100,000노드·2,000ms, 128노드 검사·task 양보를 적용한다.
- 개별 예산 초과는 제거 복구·다음 시도, 전체 예산 초과는 전체 실패다. signal 취소·난수 범위·입력 불변을 지킨다. 성능 조정은 측정 근거로 기록한다.

시연 범위: 브라우저 UI 없이 테스트 또는 개발용 모듈 호출에서 퍼즐을 만들고 풀이·해답 수·실패 결과를 확인한다.
