## 3. 작업 범위

### 포함

- src/**/*.js를 TS로 전환하고 Board·GameState·Action·생성/검증 결과·주입 함수·store 계약을 정의한다.
- 고정 TypeScript devDependency·lockfile·tsconfig·타입 검사·정적 준비 스크립트·최신 출력 대상 테스트를 마련한다.
- .build/ 개발 출력과 dist/ 게임 전용 공개 출력, 로컬 정적 서버 대상·MIME·경계 검사를 정비한다.
- AGENTS 수정안의 허용 범위를 구현 시작 때 적용하고 실제 검증 후 현재 명령/구조로 확정한다.
- GitHub Pages를 검증된 dist의 Actions 배포로 전환하고 기존 공개 주소에서 로딩·입력·시간·완료를 확인한다.

### 제외

숫자 디자인·보조 옵션·최근 입력·실행 취소·저장·모바일 패키징·React/Next.js·번들러·서버 API. scripts/Node 테스트/브라우저 fixture의 전면TS 전환.

### 유지할 제약

고정 단서·유일해 생성·실패/취소 계약·DOM 독립 core·불변 상태·포커스·외부 폼 키 정책을 유지한다.
정답 비교 힌트·후속 기능을 임의로 합치지 않는다. 런타임 외부 라이브러리·CDN·번들러는 추가하지 않는다.

## 기술 계약과 시연 범위

[AGENTS 수정안](../docs/plans/agents-typescript-proposal.md)과공통 계획 007절을 따른다.
실행용 의존성은없고TypeScript는개발 도구다. 현재 루트의 npm 금지 규칙을무시하지 말고 007실제 시작 때사용자 확정된수정안을적용한다.
tsc strict·noEmitOnError·명시적module/target/resolution으로ESM .js출력을 검증한다. 런타임assertBoard/Action검증은보존한다.
정적 배포에원본.ts·docs·tests·scripts·package/config가섞이면안된다. 소스맵 공개 여부를명시하고기본 공개 출력에서는제외한다.
.build/dist를매번재생성하고테스트가옛src/*.js나캐시출력으로통과하지않게한다. npm ci가능한lockfile을커밋대상으로둔다.
타입/검사/빌드 실패는Pages업로드/배포를중단해야한다. 기존게시본을보존하고실제배포검증 전D-001을대체됨으로바꾸지않는다.

예정 변경 위치: src/*.ts·공통 타입, tsconfig.json, package.json/package-lock.json, .gitignore, scripts의빌드/서버·tests의import/HTTP, .github/workflows의Pages 배포, AGENTS/README/architecture.
아래 위치·명령은 구현 시 실제 파일/설정에서 확인하며 없는 파일을 이미 존재하는 것으로 보고하지 않는다.
